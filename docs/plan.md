# План проверки Master_promt.md и запуска вертикального среза

## Решение о готовности промпта

Промпт достаточно готов по архитектуре и scope, но шаблонные параметры изначально требовали уточнения.
Для стартового bootstrap приняты Godot 4.7+, одна рабочая среда на Windows и Linux/Docker для headless-сервера.

## Что найдено

1. Незаполнены переменные: версия Godot, состав команды, опыт участников.
2. В проекте нет `project.godot`; сейчас в репозитории только README и сам промпт.
3. В контексте указана разработка в Ubuntu/VirtualBox, но фактическая рабочая среда — Windows. Нужно выбрать основную среду разработки.
4. Каталог в схеме назван `repo/`, хотя проект находится корнем репозитория. В промпте надо исключить лишний уровень `repo/`.
5. Не задана точная версия Godot 4, поэтому нельзя однозначно проверить актуальность API и создать совместимый проект.
6. Нет закрытого списка форматов JSON-схем и имен ключей предметов, способностей, мобов и квестов.
7. Не описаны форматы opcode/auth/handshake и правила версионирования протокола.
8. Не указаны ограничения размеров пакетов, лимиты частоты и таймауты сессии; правила в промпте общие, но реализация потребует конкретных значений.
9. Требование «один канал unreliable для снапшотов, один reliable для событий» означает два канала для конкретной реализации ENet и должно быть закреплено в протоколе.
10. PostgreSQL не описана как обязательная локальная и Docker-конфигурация для разработки; это должно стать частью bootstrap Phase 1.

## Предлагаемые решения до начала разработки

- Закрепить одну LTS-совместимую версию Godot 4 и использовать только API этой ветки.
- Для Windows-разработки использовать редактор Godot и native PowerShell-команды; Ubuntu/Docker считать серверной средой и проверить, что Docker-конфигурация не зависит от дисплея.
- Снять шаблонные поля в промпте или заменить их конкретными текущими значениями.
- Переместить описание структуры без верхнего `repo/`: корень репозитория равен корню Godot-проекта.
- Вынести числа протокола и сетевые лимиты в JSON-конфиг сервера и shared-конфигурацию.

## Рекомендуемая последовательность Phase 1 и следующих фаз

### Phase 0 — подготовка спецификации

- Зафиксировать версию Godot, ОС разработки, режим запуска и состав команды.
- Обновить Master_promt.md: удалить шаблонные поля и исправить разметку репозитория.
- Зафиксировать минимальные JSON-схемы и naming conventions.
- Зафиксировать пакетный протокол: версия, handshake, opcode, codec, каналы, лимиты.
- Подготовить базовые ADR для авторитарного сервера и сетевой архитектуры.

### Phase 1 — пустой запускаемый проект

- Создать `project.godot`, корневую структуру из промпта и headless entry point сервера.
- Настроить базовый bootstrap клиента и сервера без игрового контента.
- Добавить shared-реестр конфигурации и протокола.
- Настроить GUT unit tests и минимальный integration harness.
- Проверить: клиент запускается, сервер запускается через `--headless`, сервер не обращается к UI.

### Phase 2 — сеть и базовая сессия

- Реализовать ENet listener, session, packet router, длину/версию/валидацию пакета.
- Добавить два канала: unreliable snapshots и reliable events.
- Реализовать hello/handshake и reject/timeout для невалидных сессий.
- Обновить `docs/protocol.md` и интеграционный тест двух клиентов.

### Phase 3 — симуляция и авторитетный мир

- Реализовать общую детерминированную movement-систему для клиента и сервера.
- Добавить CharacterBody3D-адаптеры только на уровне платформы.
- Реализовать zone, entity registry, interest management и server snapshot.
- Реализовать client interpolation и prediction только для собственного движения.

### Phase 4 — данные и PostgreSQL

- Добавить JSON-регистры предметов, способностей, мобов и квестов.
- Реализовать загрузку реестров и валидацию обязательных полей/enum/значений.
- Подключить Docker/PostgreSQL, migrations и repositories для персонажа.
- Добавить тесты загрузки данных и целостности БД.

### Phase 5 — вертикальный gameplay-срез

- Реализовать Health, Stats, Combat и базовый один класс с пятью способностями.
- Добавить 8–12 мобов, мини-босса, спавн/респавн и базовый loot.
- Добавить инвентарь 20 слотов, экипировку и 15–20 предметов.
- Реализовать kill/collect/talk-квесты, NPC-диалоги, торговца и party до 5 человек.
- Реализовать say/party/system chat и сохранение персонажа.

### Phase 6 — client UI и локализация

- Создать login, char_select, world и минимальные UI-сцены.
- Подключить русские и английские ключи локализации с первого игрового экрана.
- Исключить hardcoded UI-текст и hardcoded gameplay-числа.

### Phase 7 — deployment и нагрузочная проверка

- Собрать Dockerfile.server и docker-compose для сервера с PostgreSQL.
- Запустить headless-сервер в Docker.
- Запустить два реальных клиента и автоматизированных ботов.
- Проверить протокол, disconnect, повторное подключение, battle/loot/quest/party persistence.
- Целевая проверка: устойчивость 50 одновременных игроков на одном процессе сервера.

- [x] Убраны шаблонные поля или заполнены фактическими данными.
- [x] В структуре репозитория нет лишнего `repo/`.
- [x] Зафиксированы каналы ENet, envelope пакета и список opcode.
- [ ] Зафиксированы JSON-схемы и минимальные сетевые лимиты.
- [ ] Решено локальное окружение для PostgreSQL и Docker.

## Текущий статус реализации

- Phase 0: завершена для стартового bootstrap. Зафиксированы Godot 4.7+, Windows для разработки и Linux/Docker для сервера.
- Phase 1: добавлены `project.godot`, entry point клиента, headless bootstrap сервера, protocol constants, unit-check и базовые docs.
- Runtime-проверка выполнена для Godot 4.7.2: unit-tests и загрузка основной сцены прошли успешно.
- Headless-серверный bootstrap запускается и использует проверку `DisplayServer.get_name()` для режима без дисплея.
- Docker пока не найден в `PATH`; проверка контейнерного запуска перенесена на следующую инфраструктурную задачу.
- Phase 2: завершена. Реализованы shared packet codec, server listener/session, ENet channels и handshake opcodes.
- Godot ENet резервирует два transport-канала для внутреннего трафика; protocol channel IDs отображаются на transport channels с offset.
- Event packets отправляются с `FLAG_RELIABLE`; snapshots используют unreliable flags.
- Успешный loopback с двумя клиентами подтвердил валидный handshake и отказ при несовместимой версии (`NETWORK_LOOPBACK_OK`).
- Unit-тесты и интеграционный runner проходят на Godot 4.7.2.
- Отдельная headless server scene успешно привязала UDP/7788.
- Phase 3: готова первая проверяемая multiplayer-песочница: общий movement config/simulation, серверная фиксированная симуляция, intents, world snapshots, WASD-клиент, локальная prediction/reconciliation и interpolation удалённых игроков.
- Loopback Phase 3 на Godot 4.7.2 подтверждён: два production `ClientNet` клиента проходят handshake, несовместимый клиент отклоняется, оба игрока попадают в snapshots и серверная позиция меняется после input (`WORLD_LOOPBACK_OK`).
- Дополнительно прошли project import, unit tests (`UNIT_TESTS_OK`) и запуск headless-сервера на UDP/7788.
- Phase 3 остаётся в работе: впереди entity registry/interest management и отдельный `CharacterBody3D` adapter; текущий milestone — минимальный sandbox, а не полный gameplay-срез.
