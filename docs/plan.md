# План разработки MMORPG vertical slice

## Целевой scope

- Godot 4.7+, GDScript; разработка на Windows, headless-сервер на Linux.
- Docker необязателен: локальный PostgreSQL можно установить нативно.
- Один класс, 5 способностей, одна игровая зона, 8–12 мобов двух типов и мини-босс.
- Лут, инвентарь на 20 слотов, экипировка на 6 слотов, 5 квестов, NPC/торговец и чат.
- PostgreSQL-персистентность и целевая проверка 50 одновременных игроков.
- Не расширять scope функциями, запрещёнными в [Master_promt.md](../Master_promt.md).

## Текущее состояние

### Завершено

- **Phase 0–1:** проект и headless bootstrap клиента/сервера; проект проверен на Godot 4.7.2.
- **Phase 2:** ENet handshake, версия протокола, codec, reliable events и unreliable snapshots.
- **Phase 3:** серверная симуляция движения, prediction/interpolation, AOI, отключение сущностей и тестовые zone transfer.
- **Phase 4 — JSON:** versioned registries items/abilities/mobs/quests, загрузка и валидация данных на старте.
- **Phase 5 — основа боя:** `starter_slash` и `heavy_strike`, training slime с серверным aggro/chase/attack, здоровье игрока, смерть и респавн; локализованный HUD.

Последняя проверенная версия — commit `425d24f`. На Godot 4.7.2 проходят импорт, unit-тесты (`UNIT_TESTS_OK`), сетевой loopback (`COMBAT_LOOPBACK_OK`) и headless smoke клиента/сервера.

### Не завершено

- **PostgreSQL:** миграции и repositories отсутствуют. Не выбран и не проверен совместимый с Godot/GDScript способ прямого подключения.
- **Phase 5:** доступны 2 из 5 способностей и один моб; нет ресурсов/уровней/полной системы характеристик, лута, инвентаря, экипировки, квестов, NPC, торговли и чата.
- **Phase 6:** login/character-select и законченный игровой UI ещё не реализованы.
- **Phase 7:** целевой Linux deployment и нагрузка 50 игроков не проверены.
- В текущем тестовом sandbox настроены две in-memory зоны; целевой вертикальный срез по промпту должен свестись к одной зоне.

## Следующие задачи по приоритету

### 1. Проверить PostgreSQL-подключение без Docker

Это следующий формальный шаг Phase 4 и блокер для персистентности.

- Установить/использовать нативный PostgreSQL для разработки на Windows.
- Проверить прямой серверный драйвер/расширение, совместимое с GDScript и Godot 4.7.2, также для Linux headless.
- Минимальный spike: подключение, параметризованный запрос, чтение результата, транзакция, обработка ошибки и закрытие соединения.
- Не писать миграции и repositories, пока способ подключения не проверен; не подменять PostgreSQL на SQLite без изменения scope.

**Готово, когда:** один и тот же серверный код проходит smoke-проверку соединения на Windows и Linux headless без Docker, а настройки/секреты не хранятся в репозитории.

### 2. Добавить минимальную персистентность персонажа

## Технические решения и ограничения

- Сервер остаётся авторитетным; клиент отправляет намерения, а не результаты боя или инвентаря.
- Docker — необязательный инструмент запуска, но PostgreSQL остаётся требованием целевого scope.
- Клиентское/серверное подключение к БД не считать реализованным до проверки драйвера на обеих ОС.
- Protocol version: `2`; при несовместимом изменении сетевой схемы обновлять версию и интеграционные тесты.
- Числа баланса и поведения брать из конфигурации/JSON, не добавлять игровые значения в логику клиента.
